    Section 5.9 A page about another page

    The searcher can now recognize proofs, but its target sentence must say something about its own work. “There is a completed record ending with 314” must be written using the language our checker understands. We will build toward that sentence using the little record \(r\text{.}\) Its three entries already stand in a definite order. Inside each entry, we must also distinguish the instruction, the card address, and the marked squares. We need to preserve both levels of order.
    🔗
    The order of the writing matters. A worker who writes 7, then 0, then 7 has written a different word from one who writes 0, then 7, then 7. Sets can hold the records, provided we label their places. Putting the symbols 7, 0, and 7 into an unlabelled bag loses the distinction between the first and last occurrence of 7. Instead attach position labels:
    \begin{equation*} \text{place 0: }7,\qquad \text{place 1: }0,\qquad \text{place 2: }7. \end{equation*}
    Keep a position label together with the mark at that position. Such a record has a first item and a second item; we call it an ordered pair. Simply putting the two items into one bag would lose their order. Here is a way to preserve it using the operations already available.
    🔗
    Let \(a\) be the first item and \(b\) the second. Begin with an empty object and adjoin \(a\text{,}\) obtaining a container \(u\) whose only member is \(a\text{.}\) To another empty object adjoin \(a\) and then \(b\text{,}\) obtaining a container \(v\) with exactly those members. Finally, to an empty object adjoin \(u\) and \(v\text{.}\) Call this last container \(p\text{.}\) We can picture its contents as
    \begin{equation*} u=\{a\},\qquad v=\{a,b\},\qquad p=\{u,v\}. \end{equation*}
    Here the braces describe the members of the chosen containers. They do not assert that there is only one container with those members. Each was obtained by beginning with an empty object and adjoining the indicated members.
    🔗
    How do we recover the two items from \(p\text{?}\) Open its inner containers. The item that belongs to every one of them is \(a\text{:}\) it belongs to both \(u\) and \(v\text{,}\) and the container \(u\) has no other member. This recovers the first item. Now look for an item in the inner containers other than that first item. If there is one, it can only be \(b\text{,}\) and it is the second item. If there is no other item, then \(b=a\text{:}\) the same item occurred twice in our ordered pair.
    🔗
    For example, with first item 0 and second item 7, the inner containers have contents \(\{0\}\) and \(\{0,7\}\text{.}\) Their common member recovers 0; the remaining member recovers 7. With first item 7 and second item 0, the inner contents are instead \(\{7\}\) and \(\{7,0\}\text{.}\) The common member is now 7. The construction has remembered which item came first even though membership itself has no order. The numerals here name the objects used to represent our position labels and digit marks.
    🔗
    The repeated pair \((7,7)\) also works. Both inner containers have only 7 as a member. They might be the same object, or they might be different objects with the same contents; either way, the recovery procedure gives 7 first and, because there is no other member, 7 second. We have used no rule identifying containers merely because their members agree. Different containers can represent the same ordered pair, but each valid representation fixes its two entries.
    🔗
    Now make pairs representing \((0,7)\text{,}\) \((1,0)\text{,}\) and \((2,7)\text{,}\) and collect those pair records by adjunction. The two occurrences of 7 no longer collapse: their position labels differ. Looking up the entry with label 0 gives 7, label 1 gives 0, and label 2 gives 7. We have stored the word 707 using containers while retaining the order of its writing. In entry 1 of \(r\text{,}\) the same pairing construction attaches the address \((0,0,0)\) to its mark 7. The address is itself a three-entry record, formed by attaching position labels to its page, column, and row. A further pair attaches the label “marked squares” to the collection of marked-square entries. Putting that information beside the card and instruction records completes the configuration. The operation is repeated at each level: attach a label, then collect the labeled entries.
    🔗
    A configuration has several such records: one for the marked squares, one for the positions on the place cards, and one for the next instruction. Number the successive configurations and attach each number to its configuration in the same way. A computation is then a sequence of configurations, each itself assembled from finite records. It is the sequence-of-sequences picture developed from the worker’s calculation.
    🔗
    Here is one local check written in the set language. Call the marked-square container in entry 1 \(m\text{.}\) Let \(a\) name the code for address \((0,0,0)\text{,}\) and let \(s\) name the code for the mark 7. We want to say that \(m\) contains an entry whose first item is \(a\) and second item is \(s\text{.}\) Use fresh names \(t,u,v\) for the entry and its two inner containers:
    \begin{equation*} \begin{split} \exists t\exists u\exists v\,\bigl(&t\in m\ \land\\ &\forall z(z\in u\leftrightarrow z=a)\ \land\\ &\forall z(z\in v\leftrightarrow(z=a\lor z=s))\ \land\\ &\forall z(z\in t\leftrightarrow(z=u\lor z=v))\bigr). \end{split} \end{equation*}
    Read each line beside the picture of the pair. The entry \(t\) belongs to the marked-square container. Container \(u\) has just \(a\) as its member. Container \(v\) has exactly \(a,s\text{.}\) Container \(t\) has exactly \(u,v\text{.}\) The sign \(\leftrightarrow\) says “if and only if”: both directions must hold. Thus “\(z\in u\) if and only if \(z=a\)” both puts \(a\) in \(u\) and rules out all other members. This sign abbreviates two implications joined by “and,” so it adds no new proof move.
    🔗
    For the actual write-7 step, construct \(u,v,t\) by adjunction and put \(t\) into \(m\text{.}\) The adjunction axioms give the displayed membership descriptions. The example rule, applied to these chosen objects, verifies the existential statement. For a proposed write-9 step the second item would instead be the code for 9; it would fail the required comparison with the code for 7. Distinct symbol codes are part of the record convention. We must still check the address code, the next instruction, and every unchanged component. This one formula checks only the specified marked entry. It does not certify the whole transition on its own.
    🔗
    We can build a particular record and express a particular check on it. The searcher’s sentence asks for more: a record of some length, with every step correct and 314 at the end. One fixed formula must recognize records of different lengths. It must describe how to find an entry, pass to the next one, and check the change between them. This is where a general coding theorem enters the argument.
    🔗
    These two set-building principles have surprising strength. The philosopher Zlatan Damnjanovic showed that adjunctive set theory, with or without extensionality, and the weak system called Robinson arithmetic can represent each other. For the uniform coding of our computation records, we also use Albert Visser’s work on pairs and sequences. The bridge is a translation: a claim about a finite written record becomes a sentence about sets, and the elementary checks on that record become proofs using our rules. The translation must preserve positions and repeated symbols, rather than merely collect the symbols that occur. The appendix describes the record format and identifies the coding results on which the next argument depends.
     1 
    Damnjanovic, “Mutual Interpretability of Robinson Arithmetic and Adjunctive Set Theory with Extensionality,” Bulletin of Symbolic Logic 23 (2017), 381–404, doi:10.1017/bsl.2017.30; Visser’s sequence-coding references are listed in the appendix and source notes.
    🔗
    Let us try one small translation before using that bridge. In number language we say, “Every number has a successor.” In the set language, we first need a test for which objects represent numbers. Write \(\operatorname{Num}(x)\) for that test and \(\operatorname{Succ}(x,y)\) for the test saying that \(y\) represents the successor of the number represented by \(x\text{.}\) The translation has this shape:
    \begin{equation*} \forall x\bigl(\operatorname{Num}(x)\ \longrightarrow \exists y(\operatorname{Num}(y)\land\operatorname{Succ}(x,y))\bigr). \end{equation*}
    Start with any object \(x\) in the world. If it fails the number test, this sentence asks nothing more of it: a bag need not be a number code. If it passes, we must find another passing object \(y\) and check the successor relation. For a code representing 2, that means finding a code representing 3. Two different passing objects may represent the same number, just as different containers can represent the same pair.
    🔗
    Try a small example with ordinary cards before returning to sets. Allow cards of the form \((n,\text{red})\) and \((n,\text{blue})\text{,}\) where \(n\) is an ordinary nonnegative integer. Our number test accepts exactly these cards. It rejects a card saying only “Monday.” The cards \((2,\text{red})\) and \((2,\text{blue})\) are different pieces of data, but our equality test ignores their colours and compares their numbers: they represent the same number. Write \(\operatorname{EqNum}\) for that test. The successor test also ignores colour. It accepts \((2,\text{red}),(3,\text{blue})\text{,}\) and still accepts if either colour changes; it rejects \((2,\text{blue}),(4,\text{red})\text{.}\) Thus translating “two equals two” does not require red to equal blue. It requires \(\operatorname{EqNum}\) to accept the chosen two codes. This card game illustrates represented equality; it is not the set theory’s actual coding scheme, which the interpretation theorem supplies.
    🔗
    In the set-language translation above, \(\operatorname{Num}\text{,}\) \(\operatorname{EqNum}\text{,}\) and \(\operatorname{Succ}\) abbreviate fixed formulas using membership, equality, and the logical signs we have learned. The borrowed interpretation theorem supplies those formulas and the proofs of their arithmetic laws. Ordinary numerals name numbers in that domain, but a model’s domain can also contain represented numbers beyond every ordinary numeral. A quantifier over represented numbers covers those too.
    🔗
    The property we first need connects an actual calculation with a proof. If a program finishes after a finite number of steps, its completed record can be turned mechanically into an AS proof that it finished with that result. The local checks we just made on \(r\) become pieces of that proof. The coding theorem lets us assemble such pieces for each supplied successful record, however long it is.
    🔗
    We call this the finite-trace property. It guarantees a formal certificate for each actual finite success. The proof may be much longer than the original record: a sentence saying that a square keeps its mark may require unpacking several definitions. Nevertheless, the translation is mechanical and finishes for each supplied successful record.
    🔗
    For our waiting program this has a sharp consequence. If it ever returns 314, its finite work will supply a proof that it returned 314. If it searches forever, there is no completed record to translate. The finite-trace property certifies a success; it does not decide whether the search will succeed.
    🔗
    Before constructing the searcher, separate two promises a proof method might make. Consistency says that it never certifies both a sentence and that sentence’s negation. Truth in the intended calculation says that everything it certifies correctly describes the ordinary worker on our paper. The second promise is stronger. The first only forbids the conflicting pair; by itself it does not select which member of a pair is correct.
    🔗
    Our coming argument assumes consistency and uses one specific bridge to ordinary calculation: every actual finite success supplies a positive certificate. Keep that bridge beside the rulebook. If a certificate makes the worker perform a finite calculation, we can write down that calculation and obtain its certificate too. It is these two certificates, with opposite conclusions in the same proof method, that will cause the contradiction. We will not need to assume that every other sentence the method certifies is true on our desk.
    🔗
    Later we will compare an ordinary calculation with a record inside a mathematical model. That comparison uses one further part of the coding laws: every starting condition and every instruction must have its specified effect. For the record \(r\text{,}\) the move step must preserve all the marked squares. A record that puts an extra 8 somewhere else fails, even though the 7 and the place card are correct. Preserving unmentioned components matters as much as making the requested change.
    🔗
    The interpreted coding must preserve these initial conditions, local updates, and comparisons. Different codes for the same configuration are harmless; a different decoded configuration is not. These are part of the representation laws we borrow, spelled out for our record format in the appendix. For a sheet that keeps working, apply them to five steps, and a model’s first five steps agree with ours. Apply them a million times, and its first million agree. This is an argument we make for each ordinary finite stretch of work; it does not say that every length the model calls finite is a length our worker can finish counting.
