    Section B.6 Configurations, traces, and the output predicate

    A configuration code records the instruction label, the worker’s named place cards, and a finite table of marked squares. Each place card records a triple \((p,i,j)\text{:}\) page, column and row. A marked-square entry gives such a triple together with the symbol written there. Entries are ordered by their coordinates, duplicate coordinates are disallowed, and every omitted square is blank. Coordinates are finite integer strings under the fixed writing convention. The input, returned result and permanent decimal output have their specified places in the record. At any actual finite stage there are only finitely many written symbols and place cards to record.
    🔗
    The relation \(\operatorname{Step}(e,c,d)\) reads the instruction selected in \(c\) and checks the corresponding change in \(d\text{:}\)
    🔗
    • Move(A,dp,dx,dy) adds the three indicated displacements to the coordinates on card A.
      🔗
      🔗
    • Place(A,B) copies the coordinates from card B onto card A.
      🔗
      🔗
    • Write(A,s) puts symbol s in the square named by card A; writing blank removes that square’s marked entry.
      🔗
      🔗
    • If(A,s) Goto L chooses between line L and the following line by comparing the symbol at A’s square with s.
      🔗
      🔗
    • IfSame(A,B) Goto L makes the same choice by comparing the coordinate triples on the two cards.
      🔗
      🔗
    • Goto L selects line L; Halt marks a completed computation.
      🔗
      🔗
    The first three instructions proceed to the following line. Every clause also checks that all components outside the specified change agree. Coordinate arithmetic, copying and comparison are finite string operations. Abbreviated tasks use the fixed expansion into these instructions; a record follows the expanded sheet. A trace begins with the prescribed input and place cards, continues through configurations linked by \(\operatorname{Step}\text{,}\) and, for a completed computation, ends at Halt. Thus the computation is recorded as a sequence of sequences: successive configurations of the paper and the worker’s places.
    🔗
    Our little write–move–halt program makes the checks visible. Card \(A\) starts at \((0,0,0)\) on blank working paper; the instructions are Write(A,7), Move(A,0,1,0), Halt. There are three configurations at instruction boundaries. First the marked entry \(((0,0,0),7)\) is added and the instruction label advances. Next that entry stays put, the card changes to \((0,1,0)\text{,}\) and the label advances to Halt.
    🔗
    Try changing the mark’s coordinate along with the card. The checker rejects the certificate: moving attention does not move the mark. Try adding an unexplained second mark, and the unchanged-component requirement rejects it. A correct-looking answer cannot excuse either alteration. The clauses of \(\operatorname{Step}\) check how the paper changed.
    🔗
    For use across models, the interpretation must prove that the initial configuration has the prescribed decoded data and that each nonhalting instruction has a unique decoded successor, with the unchanged-component clauses above. Uniqueness is up to represented equality, not literal identity of code objects. The interpreted arithmetic and sequence laws supply the comparisons and record access used in these clauses. For each ordinary finite number of transitions, repeated application therefore fixes the decoded configurations to be the ordinary ones. A record cannot end at such a stage unless its selected instruction is Halt. This ordinary-stage fidelity uses those representation laws and the deterministic definition of \(\operatorname{Step}\text{.}\) It does not follow from consistency alone or merely from the positive finite-trace promise. Nor does the external repetition assert that every internally finite record has ordinary length.
    🔗
    Formally, the abbreviation \(\operatorname{Out}(e,w)\) is obtained by applying the fixed coding interpretation to the assertion that such an accepting record exists with final output \(w\text{.}\) The checker and the programs that print formulas use the same coding, which remains fixed across models. An actual run supplies the record; the representation theorem supplies a formal proof. A model may also satisfy the same existential formula through a record with nonstandard interpreted length, extending beyond every ordinary finite record we can put on paper.
    🔗
    For the final long division, fasten the relevant records together. The certificate carries one common witness: both completed program records, their numeral outputs, and a single division record. The division record is a finite initial segment of the perpetual decimal printer, ending at a digit boundary with remainder zero. Further zeros may be included after the first zero remainder. Every requirement on the first \(k\) digits refers to this same witness. Thus asking for another digit keeps us with the same integer outputs and the same division, rather than quietly substituting a different calculation.
    🔗
    Each numeral output includes an evaluation chain: begin at zero and, on reading a digit \(d\text{,}\) replace the previous value \(v\) by \(10v+d\text{.}\) The last values are the represented integers \(p,q\text{,}\) and the record requires \(q>0\) and \(0\leq p<q\text{.}\) The certificate must include these chains and their values in the interpreted domain alongside the numeral strings.
    🔗
    The division component also carries running arithmetic witnesses \(A_i,B_i,R_i\text{.}\) An index is a position label: the subscript \(i\) says how many answer digits have been recorded. \(A_i\) is those first \(i\) digits read as an integer, \(B_i=10^i\) is 1 followed by \(i\) zeros, and \(R_i\) is the remainder after that digit. At position zero no digits have yet been written, so \(A_0=0\text{,}\) \(B_0=1\text{,}\) and \(R_0=p\text{.}\) These letters translate Chapter 2’s notation: its accumulated answer \(B\) is our \(A_i\text{,}\) and its factor \(10^k\) is our \(B_i\text{,}\) with \(k=i\text{.}\)
    🔗
    For \(p=3140,q=10000\text{,}\) the first digit is 3. Thus \(A_1=3,B_1=10,R_1=1400\text{,}\) and the check is
    \begin{equation*} 3140\mathbin{\times}10=10000\mathbin{\times}3+1400. \end{equation*}
    The next digit is 1. Hence \(A_2=31,B_2=100,R_2=4000\text{,}\) and
    \begin{equation*} 3140\mathbin{\times}100=10000\mathbin{\times}31+4000. \end{equation*}
    Both remainders are nonnegative and smaller than 10000. Reading \(i+1\) in the general rule means moving to the next such line; \(d_{i+1}\) is the new digit on that line. The conditions are
    \begin{equation*} \begin{gathered} B_0=1,\quad A_0=0,\quad R_0=p,\\ B_{i+1}=10B_i,\quad A_{i+1}=10A_i+d_{i+1},\\ pB_i=qA_i+R_i,\qquad0\leq R_i<q. \end{gathered} \end{equation*}
    The final recorded remainder is zero. The definition of a valid record requires these equations at every recorded position, including positions in a nonstandard trace. Every actual record produced by the construction has these witnesses. The integer checks let us compare the ratio \(p/q\) with decimal endpoints without performing an endless division. Technically, ratios are formed from the interpreted ordered integers in their fraction field: a fraction is a numerator and a nonzero denominator, equal fractions are identified by cross-multiplication, and sums and products use the familiar fraction rules. The ordered arithmetic supplied by the interpretation justifies those rules. For positive denominators, for example, comparing \(p/q\) with \(31/100\) means comparing \(100p\) with \(31q\text{.}\)
    🔗
    Each prefix formula includes the preceding one as a conjunct. Let \(\operatorname{Digit}_i(D,d)\) say that the output string in the division component of \(D\) has digit \(d\) at the position named by the ordinary index \(i\text{,}\) using the fixed sequence interpretation. For the empty word put \(\operatorname{Prefix}_{\varnothing}(D)\) equal to \(D=D\text{.}\) The quantities \(p\) and \(q\) below are the numerical values decoded from this same record \(D\text{.}\) In the fully expanded formula their codes are bound together with the clauses identifying the record’s two numeral outputs; they are not additional freely chosen numbers. If \(s\) has ordinary length \(k\text{,}\) define the formula for its extension by the digit \(d\) to be
    \begin{equation*} \begin{split} \operatorname{Prefix}_{sd}(D):={}& \operatorname{Prefix}_{s}(D)\land \operatorname{Digit}_{k+1}(D,d)\\ &\land\bigl(q a_{sd}\leq 10^{k+1}p <q(a_{sd}+1)\bigr). \end{split} \end{equation*}
    The joined letters \(sd\) mean the word \(s\) with the single digit \(d\) appended; they do not mean multiplication. For example, take \(s=3\) and \(d=1\text{,}\) so \(sd=31\text{,}\) \(k=1\text{,}\) and \(a_{sd}=31\text{.}\) The formula keeps the requirement for the first digit 3, adds the requirement that digit 2 is 1, and checks
    \begin{equation*} 31q\leq100p<32q. \end{equation*}
    With \(p=3140,q=10000\text{,}\) this says \(310000\leq314000<320000\text{,}\) which is true. The earlier prefix requirement has remained part of the statement, so taking that part back out recovers the first-digit assertion.
    🔗
    Here \(a_{sd}\) is the ordinary integer value of the finite word \(sd\text{.}\) Compute \(10^{k+1}\) and \(a_{sd}\) while preparing the formula, then insert their fixed ordinary numerals. This external recipe produces one finite formula for each ordinary finite word. Every longer-prefix formula entails the earlier ones by repeated conjunction elimination. The inequalities place the represented ratio in the requested decimal interval. The common record has one numeral pair and one digit string; the interpreted sequence relation supplies unambiguous entries on its domain. Its length must be sufficient for the finitely many displayed entries in any one prefix requirement.
    🔗
    If \(\operatorname{Record}_e(D)\) specifies the shared program and division record, the certificate controller can search for negations of
    \begin{equation*} \varphi_s(e):=\exists D\, \bigl(\operatorname{Record}_e(D)\land \operatorname{Prefix}_s(D)\bigr). \end{equation*}
    The controller’s response to a forbidden prefix produces the two numeral outputs and a division record with that prefix. The required verification property is this: from such an actual valid common record with prefix \(s\text{,}\) a mechanical translation supplies a \(T\)-proof of \(\varphi_s(e)\text{.}\) The fixed AS computation interpretation supplies this property for the combined record checker. Any other proof methodology used in the finale must likewise verify these common records, as well as the individual outputs. The resulting proof contradicts a certificate excluding that prefix. Having proved that \(T+\varphi_s(e)\) is consistent for every standard \(s\text{,}\) one may add a common constant naming \(D\) and use the nested prefix conditions in compactness. The witness then remains common across all ordinary finite beginnings.
